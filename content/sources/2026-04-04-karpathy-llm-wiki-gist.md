# Karpathy's LLM Wiki gist

The gist that named the pattern this wiki is built on: an LLM that compiles raw sources into a
persistent Markdown wiki, and answers from the wiki rather than the sources.

## What it says

RAG makes the model rediscover knowledge on every question, so nothing accumulates. Instead the LLM
should maintain a wiki between the reader and the sources, and queries should run against it. Human
wikis die because "the maintenance burden grows faster than the value"; with an LLM maintaining it,
"the cost of maintenance is near zero".

Three layers: immutable **raw sources** the LLM never modifies; **the wiki**, Markdown the LLM owns
entirely, holding summaries, entity pages, concept pages and cross-references; and **the schema**,
a configuration file recording the conventions and procedures.

Two special files. `index.md` is a content catalogue with a one-line summary per page, read first
at query time to decide which pages are relevant — no embeddings. `log.md` is append-only and
chronological, and a consistent date prefix keeps it parseable with unix tools.

Three operations: **ingest** (read a source, write a summary page, update the index, revise the
pages it affects, append to the log — perhaps fifteen pages for one source), **query** (answer with
citations; a good answer can be filed back as a page), and **lint** (contradictions, stale claims,
orphans, missing cross-references, gaps).

The human curates and asks; the LLM does the rest. The gist is deliberately abstract so an agent
can fit it to a setup.

## Unresolved

- The gist lists entity pages as part of the wiki layer. This wiki deleted its `person` and `org`
  types on 2026-09-11, so that half of the pattern is deliberately unimplemented.
- The gist's `index.md` is this wiki's `_index.md`, renamed for Hugo. Harmless here, but it is the
  one place the layout stops matching the pattern it came from.
