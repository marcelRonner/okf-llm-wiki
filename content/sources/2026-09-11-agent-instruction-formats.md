## What it says

Four mechanisms are called "instructions" and differ in when they enter context: always-on files,
path-scoped files loaded on a glob match, invocable operations loaded by name, and delegated agents
that run in a separate context and return a summary.

Claude Code 2.1.268 loads, per directory, only `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`
and `.claude/rules/`; skills come from `.claude/skills/`. It does **not** read `AGENTS.md` — that
name appears in the binary only in the `/init` prompt and the Codex importer. VS Code Copilot reads
`.github/copilot-instructions.md`, `AGENTS.md` and `CLAUDE.md` as always-on, and finds skills in
`.github/skills/`, `.claude/skills/` and `.agents/skills/`; its Agent Skills support is dated
2025-12-18.

So the two have converged on almost everything, `SKILL.md` and `AGENTS.md` included. They diverge in
one place that matters to a project: project-level path-scoped rules. Copilot reads those from
`.github/instructions/` and consults `.claude/rules` only at user level, so a project wanting both
must state each scoped rule twice, as `paths:` and as `applyTo:`.

Two constraints follow. Path-scoped rules attach *after* the tool call that touched a matching file,
so they cannot inform a first write to a folder; and in a Hugo repository a nested `AGENTS.md` under
`content/` would be published as a page unless excluded.
