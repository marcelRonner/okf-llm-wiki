# Open Knowledge Format specification

Google Cloud's specification for packaging knowledge as Markdown with YAML frontmatter, described as
the first vendor-neutral formalisation of the LLM-wiki pattern.

## What it says

A format, not a platform: no SDK, runtime, account, registry or manifest. A bundle is a directory of
Markdown files with YAML frontmatter, cross-linked into a graph, shipped as a git repository, a
tarball or a mounted filesystem. File path is concept identity, one concept per file, with no
mandatory top-level structure. The aim is producer/consumer independence — any agent consuming any
producer's knowledge without integration work.

`type` is the only required frontmatter key, and a concept carrying nothing else is fully conformant.
`title`, `description`, `resource` and `tags` are recommended. Extra keys and extra body sections
never break a consumer.

Two reserved filenames, both optional: `index.md` for directory listings, `log.md` for chronological
history. Links may be bundle-relative from `/`, or ordinary relative paths; the absolute form is
recommended for stability.

Conformance, §11: every non-reserved file has parseable frontmatter; every frontmatter has a
non-empty `type`; reserved filenames follow their structure where present. Consumers MUST NOT reject
a bundle over missing optional fields, unknown types or broken links.

v0.2 breaks two things — `timestamp` becomes `generated.at`, and a body `# Citations` list becomes a
frontmatter `sources` field — and adds trust metadata (`generated`, `verified` with actor and
timestamp, yielding trust tiers), lifecycle keys (`status`, `stale_after`), credibility signals on
`sources`, and an `Attested Computation` type.
