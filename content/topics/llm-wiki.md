# LLM Wiki

The architecture this wiki is an instance of, named by Andrej Karpathy on 2026-04-04
([gist](../sources/2026-04-04-karpathy-llm-wiki-gist.md)). Its claim is that an assistant should
*compile* knowledge once rather than *retrieve* it repeatedly.

The contrast is with RAG, which fetches chunks of raw text on every question. Nothing accumulates,
so a question needing five documents synthesised makes the model piece the same fragments together
again. Compiling instead means each source is read once, at ingestion, and written into pages that
already contain the synthesis.

What makes it viable is an economic argument about maintenance. Human wikis die because the
maintenance burden grows faster than the value; an assistant doing the bookkeeping moves that cost
close to zero, which is why the pattern is only a few months old despite wikis being ancient.

## The shape

Three layers: immutable **raw sources**; **the wiki**, which the assistant owns entirely; and **the
schema**, holding the conventions and procedures. Two special files: a content catalogue read first
at query time to find relevant pages, and an append-only chronological log. Three operations —
ingest, query, lint — with provenance by citation and contradictions flagged rather than absorbed.

Read [How this wiki works](how-this-wiki-works.md) for how each of those is realised here, and
[Agent instruction formats](agent-instruction-formats.md) for where the schema layer physically
lives.

## Where this wiki departs from it

- **A fourth operation.** `/note` records things the owner simply knows. The gist assumes every
  fact arrives as a document; the monthly owner-notes page is what keeps such a fact citable.
- **Typed pages.** `schema.yml` fixes five page types and the folder each lives in. The gist leaves
  categories to the implementer.
- **No entity pages.** The gist's wiki layer holds entity pages alongside concept pages. This wiki
  has no person or organisation type, so "who does what" is recorded on the project, system or
  decision it concerns.
