# Agent instruction formats

Coding agents are configured by Markdown files, and four different kinds get called
"instructions". They differ in *when* they reach the model, which is what makes the choice between
them matter rather than cosmetic.

| Kind | When it loads | Claude Code | Copilot |
|---|---|---|---|
| Always-on | every request | `CLAUDE.md` | `AGENTS.md`, `copilot-instructions.md` |
| Path-scoped | on touching a matching file | `.claude/rules/` (`paths:`) | `.github/instructions/` (`applyTo:`) |
| Invocable operation | when named | `.claude/skills/` | `.claude/skills/`, `.github/prompts/` |
| Delegated agent | when handed a task | `.claude/agents/` | — |

As of 2026-09-11 the two tools have converged on nearly all of it. `SKILL.md` is a cross-tool
standard read from the same directories by both, and both read `AGENTS.md` — Copilot natively,
Claude Code only through an import, since its loader looks for `CLAUDE.md` and never for
`AGENTS.md`.

They diverge in one place that matters to a project: **project-level path-scoped rules**. Copilot
reads those from `.github/instructions/` and consults `.claude/rules` only for a user profile, so a
repository serving both has to state each scoped rule twice, in two dialects. That is the one thing
this wiki generates rather than writes once.

## Why a delegated agent is a different animal

The first three all run in the conversation you are already having. An agent gets a blank context of
its own and returns a summary. That makes it right for a wide read-only survey and wrong for
anything whose input must survive intact — a summary boundary is where exact wording stops being
exact. It also cannot be invoked by typing a name.

## Two constraints worth remembering

Path-scoped rules attach *after* the tool call that touched a matching file, so they cannot inform
the **first** write to a folder. A routing table in the always-on file is the manual substitute.

In a Hugo repository, per-directory instruction files are a trap: anything named `AGENTS.md` under
`content/` is published as a page unless the config excludes it.
